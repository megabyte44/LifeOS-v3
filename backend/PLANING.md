# LifeOS Backend — Implementation Plan

> **Tech Stack:** Spring Boot 4.0.3, Java 17, PostgreSQL, Flyway, Firebase Auth, Lombok  
> **Package:** `com.lifos.backend`  
> **Server Port:** 8000  
> **Total Endpoints:** ~55 across 14 domains  

---

## Architecture Overview

```
HTTP Request
    │
    ▼
┌─────────────────────────┐
│  Firebase Auth Filter    │  ← Verifies Bearer token, extracts uid
└──────────┬──────────────┘
           ▼
┌─────────────────────────┐
│  REST Controller         │  ← Handles HTTP methods, request/response shaping
│  (@RestController)       │
└──────────┬──────────────┘
           ▼
┌─────────────────────────┐
│  Service Layer           │  ← Business logic, validation, transformations
│  (@Service)              │
└──────────┬──────────────┘
           ▼
┌─────────────────────────┐
│  Repository Layer        │  ← Database queries (auto-generated by Spring Data JPA)
│  (JpaRepository)         │
└──────────┬──────────────┘
           ▼
┌─────────────────────────┐
│  PostgreSQL Database     │  ← Tables created by Flyway migrations
└─────────────────────────┘
```

### Package Structure
```
com.lifos.backend/
├── LifeOsBackendApplication.java
├── config/           # CORS, Security, Firebase config
├── security/         # Firebase auth filter, SecurityContext helpers
├── entity/           # JPA entities (map to DB tables)
├── repository/       # Spring Data JPA interfaces
├── service/          # Business logic
├── controller/       # REST endpoints
├── dto/              # Request/Response DTOs
└── exception/        # Custom exceptions + global handler
```

### Security Flow
```
Frontend (login) → Firebase Auth → Gets ID Token
Frontend (API call) → Authorization: Bearer <token> → Backend
Backend → FirebaseAuthFilter → Verify token → Extract uid → SecurityContext
Controller → Get uid from SecurityContext → Query user-scoped data
```

## Key Decisions

1. **All IDs are UUIDs** — generated server-side, stored as `uuid` in Postgres
2. **JSONB for flexible fields** — habit completions, note content, workout splits, preferences
3. **Flyway for migrations** — explicit SQL, versioned, production-grade
4. **Firebase Auth** — verify tokens server-side, extract uid, auto-create user on first request
5. **Amounts in cents** — transactions store integers to avoid floating-point issues
6. **No auth in Phase 1** — build and test CRUD first, add auth in Phase 2, retrofit
7. **Credential encryption** — AES-256 for passwords/PINs stored at rest
